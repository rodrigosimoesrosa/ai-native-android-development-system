# ADR-0015: `timeout` run-health outcome, produced by the neutral harness

- **Status:** Proposed (design decided; formal acceptance by the maintainer at the spec-007 merge gate)
- **Date:** 2026-08-13
- **Deciders:** Project maintainer
- **Related:** [ADR-0009 (run modes — ai-paced on_failure / bounded-retry)](ADR-0009-run-modes-human-paced-and-ai-paced.md) *(this outcome is generated by that contract)*, [ADR-0014 (LLM diagnostic telemetry — outcome vocabulary)](ADR-0014-llm-diagnostic-telemetry-traces-logs-evals.md) *(shares the `Provenance-Outcome` field; different producer)*, [ADR-0013 (per-commit metrics)](ADR-0013-per-commit-token-cost-aggregate.md), [ADR-0010 (automated provenance)](ADR-0010-automated-provenance-and-metrics.md), [ADR-0001 (neutral core, adapters)](ADR-0001-build-on-existing-tools-neutral-core.md), [ADR-0008 (methods/adapters layout)](ADR-0008-methods-and-adapters-layout.md), [spec 007](../specs/007-ai-paced-brain-timeout/spec.md)

---

## Context

Spec 007 hardens the tool-neutral ai-paced harness so a **hung brain call can no longer block the
loop**: a liveness watchdog kills a brain that goes silent (idle-timeout) or runs too long (hard-cap),
and the stall is folded into the existing bounded-retry (ADR-0009). A run that ends because of stalls
needs to be **legible in the run-health ledger** — distinct from "the brain returned failures".

[ADR-0014 §3](ADR-0014-llm-diagnostic-telemetry-traces-logs-evals.md) already defined the
`Provenance-Outcome` vocabulary — `ok | error | refusal | cutoff | cancelled`. But ADR-0014 is
explicitly **adapter-scoped diagnostic telemetry**: its outcome values are *model-level* signals
(`refusal`, `cutoff`) produced **inside an adapter**. The spec-007 `timeout` is different in origin: it
is produced by the **neutral core** — the harness watchdog in `scripts/` — as a **process/liveness**
event, with no adapter or model involvement. Folding a core-produced outcome into the adapter-scoped
ADR-0014 would blur exactly the core/adapter boundary (Principle V) that ADR-0014 exists to protect.

This ADR gives the `timeout` outcome its own, correctly-layered home.

## Decision

### 1. `timeout` is a first-class run-health outcome owned by the neutral harness

Add `timeout` to the `Provenance-Outcome` enum:

```
Provenance-Outcome: ok | error | cancelled | timeout    # (+ adapter-level refusal | cutoff, ADR-0014)
```

Semantics, by producer:

| Outcome | Meaning | Produced by |
|---|---|---|
| `ok` | plan complete, gate green | neutral harness |
| `error` | brain returned failures / gate red at stop | neutral harness |
| `cancelled` | escalated to a human, or no tasks | neutral harness |
| **`timeout`** | **run stopped because the brain stalled — watchdog killed it (hard-cap hit, or idle-timeout retries exhausted)** | **neutral harness (spec 007)** |
| `refusal`, `cutoff` | model-level terminal states | adapter (ADR-0014, deferred) |

### 2. The field is shared; the producers are layered

`Provenance-Outcome` is a single, content-free, git-native field (ADR-0010/0013 — safe in git). It is
written by whichever layer observed the terminal state:
- **Harness-level** outcomes (`ok`/`error`/`cancelled`/`timeout`) — the neutral core sets them from
  loop control (ADR-0009). `timeout` joins this set.
- **Model-level** outcomes (`refusal`/`cutoff`) — an adapter may set them (ADR-0014, dormant).

No adapter is required to know about `timeout`; no core code learns about `refusal`/`cutoff`. The
git-native field stays uniform for cross-adapter comparison (`scripts/metrics.sh`).

### 3. `timeout` is distinct from `error`

`error` = the brain *ran and failed* (returned non-zero, or the gate is red). `timeout` = the brain
*stopped responding* and was killed. Conflating them would hide the single most important diagnostic
signal spec 007 exists to surface (FR-007, SC-005). `scripts/metrics.sh` counts `timeout` under its
own label, never folded into `error`.

## Consequences

### Positive
- Correct layering: a **core-produced** outcome lives in a **core-scoped** ADR; ADR-0014 stays clean as
  the adapter-scoped diagnostic decision (Principle V preserved).
- The ledger can answer "did this run *hang*?" distinctly from "did it *error*?" — the exact blind spot
  behind the spec-005 incident that motivated spec 007.
- Content-free and git-safe (ADR-0013 invariant): only the enum crosses to git, never brain I/O.

### Negative / costs
- Two ADRs now touch the `Provenance-Outcome` vocabulary (0014 + 0015); readers must cross-link. Kept
  crisp by the producer table in §1.

### Neutral
- The enum is open to further values (0014's deferred `refusal`/`cutoff`); this ADR sets the pattern:
  the *producer's layer* decides the outcome's ADR home.

## Alternatives considered

1. **Amend ADR-0014 to add `timeout`.** Rejected — ADR-0014 is adapter-scoped model-diagnostic
   telemetry; `timeout` is a neutral-core process event. Placing it there blurs the core/adapter
   boundary ADR-0014 protects (Principle V). (This was the option the ai-paced brain and the plan
   flagged for the human; the maintainer chose a new ADR.)
2. **Fold `timeout` into `error`.** Rejected — loses the diagnosis spec 007 is built to provide
   (FR-007, SC-005); a hang and a failure demand different human responses.
3. **A new trailer key (e.g. `Provenance-Stall: true`)** instead of an enum value. Rejected — outcome is
   mutually exclusive per run; a second boolean field duplicates state and complicates aggregation.
